# Agent Instructions

- Never use `curl.exe`; use PowerShell or .NET-native tooling instead.

## Chocolatey AU Packages

- Put release discovery and update logic in `update.ps1` or supporting scripts.
- Put static installation and uninstallation settings, such as file types, silent arguments, valid exit codes, architecture-specific argument names, and fixed checksum types, directly in the package's `tools/chocolatey*.ps1` files. Edit these settings directly; do not generate or rewrite them through `update.ps1` search/replace rules.
- Do not manually edit values generated by AU, such as installer URLs, checksums, or dynamically generated release notes and dependency metadata. Change the update logic and run AU to regenerate those values, retaining the relevant generated changes in the package.
- Never manually compute and write package checksums. Checksum updates must be produced by the AU script.
- The package's own `<metadata><version>` is the only `.nuspec` field that must remain unchanged for an existing package. For a new package, initialize it to `0.0`. Do not retain or commit AU-generated changes to this value.
- Edit other `.nuspec` fields as needed, including static metadata and dependencies. Regenerate fields owned by AU through the updater. Dependency `version` attributes are not the package's own `<metadata><version>`.
- Never statically define package versions in `update.ps1`. Derive versions from upstream metadata or fail/ignore when the upstream source cannot provide one.
- If an AU run changes the package's own `<metadata><version>` during validation, restore its original value (or `0.0` for a new package) before finishing and report that AU generated the change. Keep other relevant AU-generated updates.
- If the local AU run cannot complete because of missing Chocolatey extensions or environment-specific helpers, report the blocker instead of filling generated fields by hand.
- Before finishing AU package work, review `git diff` and confirm that existing package versions are unchanged, new package versions are `0.0`, checksum changes came from AU, and static package settings are defined in the package scripts.
- For package-specific commits, prefix the commit subject with the package id in parentheses, followed by a short summary. Example: `(intel-arc-graphics-driver) Fix AU update flow`.
- For meta-package groups, use the meta package id as the commit prefix when updating all related packages or all related packages except the meta package. For changes limited to one specific package, use that package id instead.
- Winget cannot and should never be used as a source of truth.
- The Wayback Machine, Internet Archive, `web.archive.org`, `archive.org`, and other web archives must not be used as package sources or update sources.
